# Workout compare and the board's insights

<!-- Moved from CLAUDE.md on 2026-11-12 so it loads only when needed. Keep it current with the code it describes. -->

Read before changing `peloton/workout_*.py`, `insight_lines.py`, the insight frames in `display/ui/last_workout_screen.py`, `settings_page/history.py`, or the push/build/export scripts.

After a workout, one to three plain insights against the rider's similar earlier workouts. Rules only, no model; the contract (`WORKOUT-COMPARE-SPEC.md`, with `BUILD-PLAN.md` and the prototype scripts these modules were ported from) is kept outside this repo, since the repo is public. Four standard-library modules: `peloton/workout_features.py` (`build_row`: three raw responses (detail, performance graph, class details) → one row, `ROW_VERSION`; bike `plan` from the callout lines through the frozen `BIKE_CURVE`; strength `asks`; `_callouts` counts only the seconds inside work segments, so a callout that runs into an arms section (pedalling optional), a floor block or the cool-down never counts those against the rider, and a callout's level is weighted by its work seconds (Joel, 2026-11-13); those callout fields are only read for the workout itself, so changing them needs no `ROW_VERSION` bump), `workout_compare.py` (`is_peer`: same discipline, class type, mode (plain/arms/floor), outdoor, length within 30%, complete, earlier; bike arms rides within 1 arms section (4b); `baseline` 365 days, else 730; bike `fill_in` from plan-nearest classes when there are 2-4 real peers, flagged), `workout_insights.py` (`insights(target, rows)`: output/pace, callouts, strength weights (movement's own history first, then the weight category), heart-rate effort, then `too_few`/`nothing`; at most three) and `workout_rows.py` (`RowStore`: `<cache stem>.workout-rows.json` beside the workout log, atomic 0600; `RawFiles`: saved responses in the `training-data/<rider>/<id>.workout.json` / `<id>.json` / `rides/<ride_id>.json` layout, so a `ROW_VERSION` bump is `import_raw`, never a refetch; `sync`: newest first, 20 a run, `LoginRequired` on a 401). `scripts/workout_insights.py --rider joel --config config.local.json [--dry-run]` is the daily run (`--dry-run`: no API calls, no writes). The 19 real-workout expectations (`tests/test_workout_compare_real.py`) read the gitignored `tests/fixtures/workout_compare/real-rows.json` from `scripts/export_compare_fixtures.py` and skip without it (CI), since the repo is public; re-export after a `ROW_VERSION` bump. `training-data/` and `*.workout-rows.json` are gitignored.

The board shows at most 2 insights (`insight_lines.MAX_BOARD_INSIGHTS`, the first allowed codes in `insights()` order) after the latest-workout page's chart slides (`rotating_details`): on 64x64 a card (`insight_card`: the sentence, what it was compared with) then bars (`insight_bars`: headline, today against the usual / a share bar / blocks, the reason); on 64x32 the bars then the sentence in 1-2 pages of 3 lines (`insight_words`); every frame holds like a chart slide and drops the discipline title and heart-rate row (`LastWorkoutScreen._insight_frame` draws before either). `insight_lines.board_view(code, facts)` (import-free, wraps by characters: the `stats` font is a fixed 4 px, 15 characters a line) gives each insight's view; the dashboard stores the list as `summary['insights']` (`board_insights`), and `last_workout_screen.insight_views` validates it, since the cache can hold anything. A movement name on the reason line scrolls via `UsernameScreen.scroll_offset`. Insight text is a softened white (`_INSIGHT_TEXT` / `insight_lines.SOFT_WHITE`, 200, 205, 215), since 255 glares beside the coloured figures. Weights read `40LB`; the word after a colon is drawn `COLON_GAP_TRIM` px closer (`_draw_words`). A tough class (`workout_insights.tough_class`, code `tough_class`: the class's `difficulty` is `TOUGH_POINTS` (1.0) or more above the median `difficulty` of the rider's usual, `usual_classes`: their last `USUAL_CLASSES` (12) classes in the same discipline from the `USUAL_DAYS` (365) before it, any class type or length, indoor and outdoor together, at least `MIN_RATED` (5); complete, rated classes only, and warm-ups / cool-downs (class type containing `USUAL_SKIP_TYPES`) and classes under `USUAL_MIN_SECS` (10 minutes) are left out on both sides, since they're rated 3-4 and pull the usual down; an easier class gets nothing; Joel, 2026-11-13, measured in the spec's 5.1a) takes the output insight's place and reuses its figures when there is one, and otherwise stands alone (a first Tabata run, a strength class), so peers play no part in it. The effort insight still follows it (it drops only beside `output_up` / `output_down`, whose text speaks to heart rate). Its facts are the output insight's, or just `noun`, plus `difficulty` / `usual_difficulty` / `rated` (the usual's size). It says USUAL where the others say TYPICAL (`insight_lines.USUAL_WORD`): the pool is habit, not similar classes. Its view is laid out by the rule, not wrapped: card `WAY TO CHALLENGE` (16 characters, edge to edge: the one line allowed past 15) / `YOURSELF!` / `YOU TOOK ON A` / `9.1 CLASS, YOUR` / `USUAL IS 7.0.` (a 10.0 class: `10.0 CLASS.` / `USUAL 7.0.`), footer `LAST 12 RIDES` (`_usual_footer`; `LAST 12 CLASSES` when the noun doesn't fit, as bootcamps don't), 64x32 one page `WAY TO` / `CHALLENGE` / `YOURSELF!`, bars headline `TOUGH CLASS`, green, the 64x64 bars' usual labelled `USUAL` (the figure's optional `usual_label`, at most 7 characters). With no output insight the bars are the two ratings on a 0-10 scale (the figure's optional `top`, `RATING_TOP`; `_bars_top`) and the bottom line is `CLASS RATING`; with one, the output bars and the arrow line below. The bars frame's bottom line is the view's `reason_parts` (`['9.1', 'arrow', 'USUALLY 7.0']`, `reason` holds it as words): `last_workout_screen._parts_line` draws it from column 1, the rating in the insight's colour, a 5x5 arrow in pixels (the font has none) on the text's rows and centred between the inks (2 dark columns each side; Joel, 2026-11-12), the rest soft white, filling columns 1-63; `_good_view` checks the parts fit. The Mac text gains `Tough ride: rated 9.1 against your usual 7.0 over your last 12 rides.`; otherwise it is unchanged, and the facts it carries for the board are `n`/`real`/`reason`/`close` (output), `noun`/`rate`/`usual_rate` (effort, Strive per minute) and `difficulty`/`usual_difficulty`/`rated` (tough class). The frames are shown behind `display.workout_insights` (default false; the settings page's Workout insights card, `page.insights_card`, after Rotation; the demo/`render_rotation.py --demo` show canned insights with `--insights` or that key in `--config`). The card also lists each rider's history on the board (`settings_page/history.py`: `rows_paths` names each rider's store as the display does, via `config.user_cache_path`, which `configured_profiles` uses too; `rider_histories` counts `workout_rows.current_board_rows`, the rows the board compares with, cached by the file's mtime and size so a Pi Zero doesn't re-read megabytes each page load; states missing / old (an older `ROW_VERSION`) / unreadable / ready) and warns when the switch is on and a rider has none. `Settings.workout_history` returns None for a config it can't follow, and the card then shows only the switch. `Dashboard._workout_insight` builds a row for each new in-scope workout from the first refresh that sees it COMPLETE (workout detail + class details, once; a strength class's detail is the one `_strength_detail` already fetched for the page, passed in as `detail`; the performance graph is the refresh's own; a failed or unfinished detail is not asked for again for `INSIGHT_RETRY_SECONDS`, an hour) and upserts it into the rider's `RowStore` (`/var/lib/peloton-led/<cache stem>.workout-rows.json`, loaded on first use and trimmed to `BOARD_DAYS`, 760, so it stays its seeded size). While the workout is settling (its first hour from `start_time`, when the graph is refetched each refresh) the details are kept in `_insight_settling` and each refresh rebuilds the row with the new graph, logging `changed while settling` when it differs (to learn whether Peloton revises a COMPLETE workout; Joel, 2026-11-11), and writing the store only then (a same-looking rebuild writes nothing, so a Pi Zero doesn't rewrite 1-2 MB every refresh of the hour); the first refresh after the hour rebuilds once more, then it stops. Views are cached per workout against `_rows_generation` and recomputed only when the store changed (peers are earlier workouts, so nothing else moves them), logging `insights changed`; only a 401 escapes, any other failure is logged and leaves no insight. Switch off: no store load, no extra calls, and cached `insights` keys are stripped at start-up; version 2's single `insight` key is dropped whatever the switch. No class details are stored (several MB measured per rider), so a class taken before still costs one call when its workout is new. The store is seeded from the Mac by `scripts/push_workout_rows.sh user@board` (builds via `scripts/build_board_rows.py`; the board's file names come from the board's config, `--board-config`, default `config.json`, since the Mac's cache names differ). Rows of an old `ROW_VERSION` are ignored on the board (no raw files there): re-push after a bump. Plan and decisions (`BOARD-PLAN.md` version 2, `BOARD-SLIDE-PLAN.md` the card + bars frames) are kept outside this repo too. Layout: `docs/64x32-NOTES.md`.

Instructor milestones (`instructor_milestone`, gold; the one insight that is not a comparison): `workout_insights.milestone_insight` / `is_milestone` (a first class, or the 5th, 10th, 25th, 50th, 100th, then every 100th) over `instructors.class_numbers`, which counts the workout log's completed workouts (every discipline; a class with two instructors counts for each, the biggest count wins) that started before this one, plus this one, so the number never moves when later workouts arrive. `Dashboard._milestone` runs it only when the log's backfill is complete (a partial log would call a 3rd class the 1st) and has no network cost; `_workout_insight` adds it with `workout_insights.with_milestone` after the leading output insight (`insight_lines.OUTPUT_CODES`, or the tough class that takes its place), before callouts, strength and effort, and it counts toward `MAX_BOARD_INSIGHTS`. It needs no row, so disciplines outside workout compare (yoga, cardio, stretching ...) and a failed row build still get it; the cached views are keyed on the row-store generation and the milestone, so a log that finishes after the first refresh adds it. The view is words only: `figure` None (`_good_figure` is skipped), one `insight_card` on 64x64 and one `insight_words` page on 64x32 (`rotating_details`), lines `YOUR 200TH` / `CLASS WITH` / `JESS SIMS!`, footer `SINCE MAR 2019` (the first class, in the workout's zone) or `WELCOME!` for a first, `KEEP IT UP!` when the first class has no date; the optional `highlight` list of words (the ordinal, or `FIRST`) is drawn in the insight's colour beside the digit words. 64x32 lines run 16 characters (`EDGE_MAX`). The Mac text (`insights()`, `scripts/workout_insights.py`) does not include it: it needs the board's log. Layout: `docs/64x32-NOTES.md`.
