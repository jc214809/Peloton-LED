# The display loop, rotation and screen times

<!-- Moved from CLAUDE.md on 2026-11-12 so it loads only when needed. Keep it current with the code it describes. -->

Read before changing `peloton_led.py`, `peloton/screen_times.py`, `peloton/goals.py`, the celebration, countdown or PR screens, or the workout page's stats.

The loop is intentionally network-free after startup — all data is prefetched before `run_display_loop()` is called.

On a multi-rider board, `configured_profiles` gives each profile its own `display` (the shared section with the rider's `weekly_goals`, `milestones` and `journey` over it), and `run_multi_user_loop` must pass that, not the shared one, to each rider's `run_display_loop`: until 2026-11-04 it passed the shared one, so per-rider goal pages never showed. `render_rotation.py` hard-codes its own goals, so it can't catch this; `test_each_rider_rotation_uses_their_own_goals_milestones_and_journey` does.

Weekly goals (`config.WEEKLY_GOAL_KEYS`: `workouts`, `minutes`, `active_days`) each get a `goal` page, in the config's key order, from `goals.weekly_progress` (Monday 00:00 to now in the rider's zone; any completed workout counts, not only streak-eligible ones). `active_days` (added 2026-11-13) is distinct local dates with a workout, capped at 7 by `validate_config`; the page's unit is the key with `_` as a space (`ACTIVE DAYS`, which fits both heights). A cache from before it reads 0 until the next refresh. No celebration or streak-reminder change goes with a goal being met.

`run_multi_user_loop` plays the logo (`display.logo_duration` seconds, unless `display.show_logo` is false) before each rider's rotation except the first one after start-up, so a single-rider board shows it once per cycle.

Screen times live in `peloton/screen_times.py` (import-free, so the settings service uses it too): `page_seconds` is each screen's configured time (`screen_durations`, else its fallback; Total workouts uses Lifetime's) raised to what it needs (`least_seconds`: 5 s a highlight on the name page (`HIGHLIGHT_SECONDS`, 2026-11-09), 12 s for Head to head on 32 rows, 8 s for the journey's two steps on 32 rows, 5 for Lifetime, 5.8 for a celebration, else 1). A time is never 0 (agreed with Joel 2026-11-08): hiding a screen is leaving it out of `rotation`, and the logo has `show_logo`. `retire_zero_times` turns an older config's 0s into those switches, in `validate_config` (with a warning), in `apply_form` (so a save writes it) and when the settings page renders. Name and highlights, Head to head (64x32) and the journey (64x32: the trip, then miles by type, only with 2+ groups) share their page's time across their frames (`detail_seconds` / `stat_seconds` / `step_seconds` in the state), holding the last frame rather than starting over. The settings page's Rotation rows show a "Shows:" line from `page.shows_for` (the same functions; `test_screen_times.py` checks it against `build_rotation_pages`), each box's `min` is `least_seconds` for the panel, a lower saved value shows and saves raised, and Latest workouts has no box (each workout page lasts every stat once). The two-page 64x32 "compact" workout layout was removed 2026-11-08 at Joel's request ("compact is stupid"): `compact_workout_pages`, `last_workout_duration` and `screen_durations.latest_workouts` still load and do nothing, and `form.RETIRED_DISPLAY_KEYS` drops them on save. Loop tests use the `instant_clock` fixture (tests/conftest.py) instead of 0-second pages.

## Milestones and the countdown

A reached milestone (`dashboard.pending_milestones`) is celebrated by `display/ui/celebration_screen.py` (`CelebrationScreen`: confetti and a rising trophy, then the number with a small raised ordinal ending (`_ordinal_line`; `_CAP_HEIGHTS` lines it up and `_COMMA_INK` closes up the comma in `2,000`, both measured once since the Pi's fonts can't be measured by drawing), or a headline / noun / subtitle, confetti drawn first so the trophy and text paint over it, every off pixel fair game; 20 fps via `frame_seconds`, which `show_and_wait` honours; `ordinal`; `milestone_noun` for the total, `discipline_noun` for a discipline's (a bootcamp keeps its own name, and `_noun_line` falls back to the last word, `BOOTCAMP`, where it doesn't fit)). `build_rotation_pages` puts it first, whatever the `milestones` section's place, and only one per pass: the newest pending total, or a discipline's (`pending_discipline_milestones`), taking turns by `pass_index` when several are due; `acknowledge_milestone` retires older pending ones and records the first showing in the cache's `milestone_shown_at`; it keeps showing until midnight that day (`goals.local_date` in `display.timezone`, else the profile's, else UTC), then moves to `celebrated_milestones`. Per-discipline milestones (`peloton/goals.py`: targets 25, 50, 100, then every 100, from Peloton's overview `totals`, not the workout log, so they match the Lifetime pages and need no backfill) are keyed `strength:500` and kept apart in `celebrated_discipline_milestones` / `discipline_milestone_shown_at`, so the old int-only `celebrated_milestones` check never sees a string; `acknowledge_milestone` takes either. The `next_milestone` section is one countdown for the total and every discipline (merged 2026-11-08 at Joel's request; there is no separate discipline section): `goals.upcoming_milestones` lists whatever is within `display.milestone_within` (5) of its target (the total's from `next_milestone`: configured `milestones`, else `milestone_step`), closest first (the total wins a tie), at most `milestone_pages` (3), so usually none. Each is a `countdown` page drawn by `display/ui/countdown_screen.py` (64 rows `3 TO GO / TILL YOUR / 600TH / RIDE` (baselines 16/25/42/54, bar at 58), and `NEXT ONE / IS YOUR / 600TH / RIDE` in the same places when one is left (4 lines since 2026-11-12, Joel's pick from 8 mock-ups; it was 3 with a squeezed `NEXT UP YOUR`), the celebration's `discipline_noun`, the total `WORKOUT`; 32 rows keep `3 MORE / TO 600 / CYCLING`, the total `WORKOUTS`; the name in `lifetime_overview.discipline_color`; `bold` 7x13B on 64 rows (the name too: `title_bold` 6x13B only for STRETCHING and MEDITATION, which don't fit in bold, since 6x13B squashed STRENGTH and WORKOUT); the name is 6x9 on 32 rows, since 5x8's narrow G and T spaced out `S TRENG TH`; `celebration_screen.ordinal_line`). A discipline's celebration uses the same fixed `STEP_CELEBRATION_WINDOW` (10) as the total's step; the old `discipline_milestone_celebrate_within` setting was dropped 2026-11-08 (ignored if present; `settings_page.form.RETIRED_DISPLAY_KEYS` removes it on save). The settings page's Milestones card (`milestone-settings`, after Goals) holds `milestones`, `milestone_step`, `milestone_within`, `milestone_pages` and each rider's `milestones`; Goals keeps weekly goals, the streak reminder and each rider's name and goals. `render_rotation.PreviewDashboard` has no celebration history, so it only celebrates a total milestone crossed within that window (it used to show 2,000TH at 2,123). The demo data has Rowing at 22 and Running at 204 so `--demo` shows both a countdown and a celebration.

## PR celebration

A PR celebration (`pr` page after a record workout) is windowed like a milestone but rolling, not to midnight (Joel, 2026-11-09): `Dashboard.should_celebrate_pr` is true for `PR_CELEBRATION_SECONDS` (24 h) after the first showing (`pr_shown_at`, `acknowledge_pr` via `_acknowledge`; then `celebrated_pr_ids`). `display.pr_max_age_days` (default null, config-only, not on the settings page) skips a PR whose summary `workout_at` is older; a cached summary without `workout_at` is never skipped.

## Workout-page stats

Workout-page stats come from `_stat_details` in `display/ui/last_workout_screen.py` (routed by equipment: bike, tread/outdoor, row, everything else). Number formats match the Peloton app (`_fmt_strive`, `_fmt_distance`, `_fmt_output`, `_whole` rounds half up). `docs/DATA-POINTS.md` records which stats Peloton sends per equipment (from the raw responses in `perf_graphs/`) against which the board shows, plus stats/screens per workout; update it when changing `_stat_details`. After the stats, `rotating_details` appends chart slides (`kind`): `graph`, `zones`, `muscles` (top 3 from `summaries.muscle_groups`; only for disciplines in `MUSCLE_DISCIPLINES`, just Strength for now, though most workouts carry `muscle_group_score`); each holds `GRAPH_FRAME_EXTRA_SECONDS` longer, and `build_rotation_pages` sizes the page from the same list.
