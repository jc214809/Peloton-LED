# The display loop, rotation and screen times

<!-- Moved from CLAUDE.md on 2026-11-12 so it loads only when needed. Keep it current with the code it describes. -->

Read before changing `peloton_led.py`, `peloton/screen_times.py`, `peloton/goals.py`, the celebration, countdown or PR screens, or the workout page's stats.

The loop is intentionally network-free after startup — all data is prefetched before `run_display_loop()` is called.

On a multi-rider board, `configured_profiles` gives each profile its own `display` (the shared section with the rider's `weekly_goals`, `milestones` and `journey` over it), and `run_multi_user_loop` must pass that, not the shared one, to each rider's `run_display_loop`: until 2026-11-04 it passed the shared one, so per-rider goal pages never showed. `render_rotation.py` hard-codes its own goals, so it can't catch this; `test_each_rider_rotation_uses_their_own_goals_milestones_and_journey` does.

Weekly goals (`config.WEEKLY_GOAL_KEYS`: `workouts`, `minutes`, `active_days`) each get a `goal` page, in the config's key order, from `goals.weekly_progress` (Monday 00:00 to now in the rider's zone; any completed workout counts, not only streak-eligible ones). `active_days` (added 2026-11-13) is distinct local dates with a workout, capped at 7 by `validate_config`; the page's unit is the key with `_` as a space (`ACTIVE DAYS`, which fits both heights). A cache from before it reads 0 until the next refresh. No celebration or streak-reminder change goes with a goal being met.

`run_multi_user_loop` plays the logo (`display.logo_duration` seconds, unless `display.show_logo` is false) before each rider's rotation except the first one after start-up, so a single-rider board shows it once per cycle.

Screen times live in `peloton/screen_times.py` (import-free, so the settings service uses it too): `page_seconds` is each screen's configured time (`screen_durations`, else its fallback; Total workouts uses Lifetime's) raised to what it needs (`least_seconds`: 5 s a highlight on the name page (`HIGHLIGHT_SECONDS`, 2026-11-09), 12 s for Head to head on 32 rows, 8 s for the journey's two steps on 32 rows, 5 for Lifetime, 5.8 for a celebration, else 1). A time is never 0 (agreed with Joel 2026-11-08): hiding a screen is leaving it out of `rotation`, and the logo has `show_logo`. `retire_zero_times` turns an older config's 0s into those switches, in `validate_config` (with a warning), in `apply_form` (so a save writes it) and when the settings page renders. Name and highlights, Head to head (64x32) and the journey (64x32: the trip, then miles by type, only with 2+ groups) share their page's time across their frames (`detail_seconds` / `stat_seconds` / `step_seconds` in the state), holding the last frame rather than starting over. The settings page's Rotation rows show a "Shows:" line from `page.shows_for` (the same functions; `test_screen_times.py` checks it against `build_rotation_pages`), each box's `min` is `least_seconds` for the panel, a lower saved value shows and saves raised, and Latest workouts has no box (each workout page lasts every stat once). The two-page 64x32 "compact" workout layout was removed 2026-11-08 at Joel's request ("compact is stupid"): `compact_workout_pages`, `last_workout_duration` and `screen_durations.latest_workouts` still load and do nothing, and `form.RETIRED_DISPLAY_KEYS` drops them on save. Loop tests use the `instant_clock` fixture (tests/conftest.py) instead of 0-second pages.

## Challenges

The `challenges` section (ROADMAP item 24, built 2026-11-14; last in the default rotation) is one `challenge` page per `peloton.challenges.shown_challenges` entry: running (`end_time` in the future, by `time.time()`), `value` above 0 and a `next` tier; soonest-ending first; each `page_seconds(display, 'challenges', ...)` (the default fallback, `overview_duration`). Skipped by choice: a challenge at 0 (Turkey Burn counts only its own 18 classes, so it sat at 0 for Joel) and one at its top tier (no `next_tier`). One on its last day still shows. `display/ui/challenge_screen.py` draws it. 64 rows ("C1", Joel's pick from `.claude/previews/challenges-ring.png`): title in gold `titles` at baseline 8 (`stats` when wider than 64 px, then words dropped from the end, never a leading month: `short_title` turns `November 2026 Rep Goal Challenge` into `NOV REP GOAL`, month abbreviated and first wherever it sat, year dropped, and `fitted_title` keeps the month and the word after it), `ring_pixels` (outer radius 21.5, 3 px, centre (32, 33.5) so the ring fills rows 12-54: 4 blank rows under the title (rows 2-7), 3 above the bottom line (rows 58-62), Joel's pick 2026-11-15 since the 7 spare rows can't split evenly; clockwise from 12 o'clock with round ends, 5x5 subsamples per pixel, over `RING_TRACK`; the subsampling is measured once in `_ring_geometry` and each fraction then costs a bisect per pixel, about 0.5 ms on a Mac, and the result is cached by `lru_cache(256)` so a rotation's intros repeat from cache), the number in `title_bold` at 36 (`ring_number`: comma dropped past 33 px, then `titles`, then `123K`), the unit in grey `stats` at 43, and `remaining_line` (`497 TO 6K`, else `497 TO GO`, else the number) at 63. The ring's colour is the next tier's (`TIER_COLORS`: bronze, silver, gold; anything else gold). Intro (Joel, 2026-11-15; `ChallengeScreen` is `animated`, `atomic_frames`, `frame_seconds` 0.05, `elapsed` reset in `on_enter`, like the journey page, whose `ease_out` it reuses): the title, unit and bottom line are there from the first frame; for `SWEEP_SECONDS` (0.8 s, 16 frames) the ring sweeps from empty to its fraction (`sweep`: ease-out, whole frames only, so each ring is one of 17 per challenge and later passes hit the cache) while the number counts up with it (`counted_shown`: Peloton's commas and decimals from `shown`, in the final fitted font, with the comma dropped or `K` applied exactly as the final text does, so it is never wider than the final); then the ring's end flashes toward white for 4 frames (`flash` / `flashed`, peak 0.7, within `FLASH_RADIUS` 4.5 px of the arc's end) and everything holds still from `INTRO_SECONDS` (1.0 s). The settled frame is the page: the README screenshot, `render_challenges.py` and `render_rotation.py` (`frame_times`) draw it settled; a screen never given `update()` draws frame 0 (empty, 0). `scripts/render_challenges.write_gifs(folder)` writes the intro as GIFs. 32 rows: `docs/64x32-NOTES.md`. The panel's look of the partly lit edge pixels and the faint track at the board's brightness is still to be checked on a real panel.

## Next booked class

The `next_class` section (ROADMAP item 19, built 2026-11-14; last in the default rotation) is one `next_class` page for `peloton.booked_classes.next_booking`: the soonest valid booking until `SHOWN_AFTER_START` (10 min) after its start, `page_seconds(display, 'next_class', ...)`; state `{'booking', 'now', 'timezone'}` (`display.timezone`, else the profile's; a bad name is UTC). `booked_classes.when` picks the words: `clock` (`10:00 AM`, day `TODAY` / `TOMORROW` / weekday under a week / `NOV 22`), `minutes` within `MINUTES_WITHIN` (an hour; minutes rounded up, so never `0 MIN`) and `now` from the start. `display/ui/next_class_screen.py` draws it. 64 rows (layout "A, tag where the bar was", Joel's pick 2026-11-14; no countdown bar, he preferred the tag in its place): icon at y 0 centred (lit rows 0-20, every icon standing on row 20; none for a discipline without one), tag block rows 23-29 (`info`, 2 px padding, `TAG_COLORS`), time in `bold` at 40, day in gold `titles` at 49, class line in the discipline's colour `stats` at 56, instructor grey `stats` at 63, each centred; `class_lines` / `instructor_lines` give wordings longest first and `fitted` takes the first within `LINE_WIDTH` (62 px), so the bootcamps and Meditation always and Strength at 120 min show the noun alone. Peloton's class title is never shown (up to 32 characters). Shared first names (`SHARED_FIRST_NAMES`: Alex, Hannah, Jess, Marcel) show the full name without `WITH`. `tests/test_next_class.py` sweeps every start (now, each minute of the last hour, each half hour for a week), the 12 disciplines at 5-120 min and the longest instructor names on both heights: nothing off the panel and the blank rows between bands stay blank. The settings switch is board-wide, like every rotation page (the roadmap asked for per rider): a rider with no booking gets no page and costs only the small reservations call. The tag pulses in the last 10 minutes (Joel, 2026-11-15) so it flags that class is starting: `pulses(state)` is true from `PULSE_WINDOW` (600 s) before the start through the page's whole showing (`now` / `STARTING`, until `SHOWN_AFTER_START`), and `on_enter` sets the instance attribute `animated` from it, so `show_and_wait` ticks (every `PULSE_FRAME_SECONDS`, 0.05 = 20 fps, atomic frames) only for such a showing; a page shown outside it (11 minutes out, tomorrow) is exactly the still page and never ticks, and a showing decides once, from its state. Only the tag block's background moves: `pulse_level(elapsed)` runs 1.0 down to `PULSE_FLOOR` (0.55) and back every `PULSE_PERIOD` (1 s), stepped to the frame, applied to the `TAG_COLORS` RGB with `round` (the white text, icon and every other line never change); `elapsed` resets in `on_enter` and a still page ignores it, so frame 0 and previews (`render_next_class.py`, `render_rotation.py` via `frame_times`, `[0.0]`) are the full-brightness page, byte for byte the README screenshot. `python scripts/render_next_class.py --gifs FOLDER` writes one cycle for both heights. 32 rows: `docs/64x32-NOTES.md`.

## Club Peloton

The `club` section (ROADMAP item 25, built 2026-11-14; last in the default rotation) is one `club` page from `peloton.club.club_page`: the cached score (`parse_score`) when there is one, else the level alone from the profile's `badge_level` (`level_from_me`, `points: None`), and nothing for `NOT_A_MEMBER` (a 404); `page_seconds(display, 'club', ...)`. State: the record plus `kind` (`gem_kind`: the level's first word, anything else `GOLD`) and `boost` (`boost_until` still ahead of `time.time()`). `display/ui/club_screen.py` draws it; `valid_page` checks the state again. The gems are hand-drawn pixel art, not Peloton's images (their shapes and colours from Peloton's badges): `GEM_ROWS` holds each shape (hexagon for bronze/silver/gold, octagon for Champion, cut diamond for Legend) at 20 px (64 rows) and 12 px (32 rows) as strings, `#` the flat top face and each other letter a facet named for the way it faces (`q` up-left to `m` down-right), shaded by `FACET_SHADES` (Champion's corner facets `qpzm` in `CHAMPION_CORNER` blue). Outlines step evenly (2 across 1 down on the hexagon, 1 and 1 on the others) and nothing is blended, so every pixel is crisp (Joel, 2026-11-14: the first version's 4x4-sampled edges looked soft). Hand-editable: change a letter, then `python scripts/render_club.py`; `tests/test_club.py` checks every grid is square with a symmetric outline. `gem_pixels(kind, size)` reads them, cached by `lru_cache`. 64 rows: gem 20 px at (22, 1); the level in its `TEXT_COLORS` `bold` at baseline 33 (`titles` past 62 px: `BRONZE II`/`III`, `SILVER II`/`III`); `13,659 PTS` in white `titles` at 42 (`points_line`: the comma, then `PTS`, dropped to fit); the bar rows 45-47 from column 3 to 60 (`_bar`: `tier_min` to `tier_max` lit in the gem colour over `BAR_TRACK`, one dark column at each of `marks`, the levels inside the tier; full with no `tier_max`); then `1,341 TO` in white `stats` at 55 and the next level in its colour at 63, or `TOP LEVEL` alone at 59; during a boost `2X` in gold `stats` at x 2 on row 63, as on 32 rows (moved from the top right at Joel's request, 2026-11-14), when it clears the next level's name by 2 px of advance, 3 blank columns (`SILVER III` and `BRONZE III` leave exactly that; a made-up 15-character name doesn't). `next_line` gives the one-line wordings (`1,341 TO CHAMPION`, no comma, `1,341 TO GO`). The level-only page is the gem, the level and `CLUB PELOTON` in grey at 63. 32 rows: `docs/64x32-NOTES.md`. `tests/test_club.py` `LARGEST` sweeps every metal, `SILVER III`, `CHAMPION`, 6-digit points, 5-digit remainders and made-up long names on both heights: nothing off the panel, nothing over the gem, clear rows around the bar.

## Milestones and the countdown

A reached milestone (`dashboard.pending_milestones`) is celebrated by `display/ui/celebration_screen.py` (`CelebrationScreen`: confetti and a rising trophy, then the number with a small raised ordinal ending (`_ordinal_line`; `_CAP_HEIGHTS` lines it up and `_COMMA_INK` closes up the comma in `2,000`, both measured once since the Pi's fonts can't be measured by drawing), or a headline / noun / subtitle, confetti drawn first so the trophy and text paint over it, every off pixel fair game; 20 fps via `frame_seconds`, which `show_and_wait` honours; `ordinal`; `milestone_noun` for the total, `discipline_noun` for a discipline's (a bootcamp keeps its own name, and `_noun_line` falls back to the last word, `BOOTCAMP`, where it doesn't fit)). `build_rotation_pages` puts it first, whatever the `milestones` section's place, and only one per pass: the newest pending total, or a discipline's (`pending_discipline_milestones`), taking turns by `pass_index` when several are due; `acknowledge_milestone` retires older pending ones and records the first showing in the cache's `milestone_shown_at`; it keeps showing until midnight that day (`goals.local_date` in `display.timezone`, else the profile's, else UTC), then moves to `celebrated_milestones`. Per-discipline milestones (`peloton/goals.py`: targets 25, 50, 100, then every 100, from Peloton's overview `totals`, not the workout log, so they match the Lifetime pages and need no backfill) are keyed `strength:500` and kept apart in `celebrated_discipline_milestones` / `discipline_milestone_shown_at`, so the old int-only `celebrated_milestones` check never sees a string; `acknowledge_milestone` takes either. The `next_milestone` section is one countdown for the total and every discipline (merged 2026-11-08 at Joel's request; there is no separate discipline section): `goals.upcoming_milestones` lists whatever is within `display.milestone_within` (5) of its target (the total's from `next_milestone`: configured `milestones`, else `milestone_step`), closest first (the total wins a tie), at most `milestone_pages` (3), so usually none. Each is a `countdown` page drawn by `display/ui/countdown_screen.py` (64 rows `3 TO GO / TILL YOUR / 600TH / RIDE` (baselines 16/25/42/54, bar at 58), and `NEXT ONE / IS YOUR / 600TH / RIDE` in the same places when one is left (4 lines since 2026-11-12, Joel's pick from 8 mock-ups; it was 3 with a squeezed `NEXT UP YOUR`), the celebration's `discipline_noun`, the total `WORKOUT`; 32 rows `3 AWAY FROM / YOUR 600TH / RIDE` (`CountdownScreen._render_short`: 5x8 top line with the count gold (cyan until 2026-11-14), 4x6 `YOUR` floating mid-number, the name 7x13B, a smaller name closing the page up; every line centred by its lit pixels; layout and the largest-value checks in `docs/64x32-NOTES.md`); the name in `lifetime_overview.discipline_color`; `bold` 7x13B on 64 rows (the name too: `title_bold` 6x13B only for STRETCHING and MEDITATION, which don't fit in bold, since 6x13B squashed STRENGTH and WORKOUT); `celebration_screen.ordinal_line`, which centres the digits plus half the `TH`, moving left only as far as keeping the `TH` on the panel needs (Joel, 2026-11-14: centring `600TH` as one piece set the digits off to the left, and the digits alone crowded the `TH` against the edge); the 64x32 countdown centres `YOUR 600TH` itself, so that line is unchanged). `scripts/render_celebration.py` draws the README's celebration screenshot (`FRAME_SECONDS` on 64x64 above 64x32); until 2026-11-14 it was drawn by hand. A discipline's celebration uses the same fixed `STEP_CELEBRATION_WINDOW` (10) as the total's step; the old `discipline_milestone_celebrate_within` setting was dropped 2026-11-08 (ignored if present; `settings_page.form.RETIRED_DISPLAY_KEYS` removes it on save). The settings page's Milestones card (`milestone-settings`, after Goals) holds `milestones`, `milestone_step`, `milestone_within`, `milestone_pages` and each rider's `milestones`; Goals keeps weekly goals, the streak reminder and each rider's name and goals. `render_rotation.PreviewDashboard` has no celebration history, so it only celebrates a total milestone crossed within that window (it used to show 2,000TH at 2,123). The demo data has Rowing at 22 and Running at 204 so `--demo` shows both a countdown and a celebration. `scripts/render_countdown.py` draws the README's countdown screenshot (its `PAGES` on 64x64 above 64x32) from `CountdownScreen`; redraw it after any countdown change. Until 2026-11-14 it was redrawn by hand and lost its 64x32 row.

## PR celebration

A PR celebration (`pr` page after a record workout) is windowed like a milestone but rolling, not to midnight (Joel, 2026-11-09): `Dashboard.should_celebrate_pr` is true for `PR_CELEBRATION_SECONDS` (24 h) after the first showing (`pr_shown_at`, `acknowledge_pr` via `_acknowledge`; then `celebrated_pr_ids`). `display.pr_max_age_days` (default null, config-only, not on the settings page) skips a PR whose summary `workout_at` is older; a cached summary without `workout_at` is never skipped.

## Workout-page stats

Workout-page stats come from `_stat_details` in `display/ui/last_workout_screen.py` (routed by equipment: bike, tread/outdoor, row, everything else). Number formats match the Peloton app (`_fmt_strive`, `_fmt_distance`, `_fmt_output`, `_whole` rounds half up). `docs/DATA-POINTS.md` records which stats Peloton sends per equipment (from the raw responses in `perf_graphs/`) against which the board shows, plus stats/screens per workout; update it when changing `_stat_details`. After the stats, `rotating_details` appends chart slides (`kind`): `graph`, `zones`, `top_lift` or `muscles` (top 3 from `summaries.muscle_groups`; only for disciplines in `MUSCLE_DISCIPLINES`, just Strength for now, though most workouts carry `muscle_group_score`); each holds `GRAPH_FRAME_EXTRA_SECONDS` longer, and `build_rotation_pages` sizes the page from the same list. A strength class Peloton's movement tracker counted (`summary['strength']`, from `summaries.strength_tracker` over the workout detail; validated again by the screen's `strength_tracker`, since the cache can hold anything) adds `TOTAL REPS`, `TOTAL VOLUME` (weight x reps; none on bodyweight classes) and `TARGETS HIT` (share of movements that hit their rep target, the value in the gold/silver/bronze tier colour, `TRACKER_TIER_COLORS`; white with no tier or `inprogress`) after Strive, and a `TOP LIFT` slide (the movement Peloton tags `most_volume`, else `most_reps`: its name on up to two lines, then reps x the heaviest weight in gold, `top_lift_text`; 64x32 gives it the whole panel, like the graph). A tracked class drops the `muscles` slide (Joel, 2026-11-13: the page would otherwise run 44 s; it's 39 s on 64x64), so an untracked one keeps it. Chosen from real-data mock-ups on 2026-11-13; rejected: one slide of all three figures (cramped, and overlaps the title and heart-rate row on 32 rows), the target streak (overlaps targets hit) and Peloton's form tip (median 24 characters, up to 53: runs off a 64x64 page and can't fit 32 rows).
