# The settings page

<!-- Moved from CLAUDE.md on 2026-11-12 so it loads only when needed. Keep it current with the code it describes. -->

Read before changing anything in `settings_page/`, `utils/wifi_setup.py` or `display/ui/settings_pin.py`.

`python -m settings_page.server` (`peloton-settings.service`, port 8080, root, its own service so a config that stops the display can be fixed; ported from LightningLane-Live-LED's). `form.py` is config ⇄ form (only shown keys change; requires the hidden `settings_form` field since unticked switches post nothing; every check is `peloton.config.validate_config` on a copy, so `load_config` and the page agree), `page.py` the HTML (inline CSS/JS, works without JS; rotation rows drag by a grip with pointer events (mouse and touch; arrow keys on the grip), a switched-off screen drops to the bottom and a switched-on one joins the end of the numbered ones; `tests/test_settings_form.py` parses it like a browser, and saving an unchanged page must load the same), `pins.py` the PIN gate, `server.py` stdlib HTTP. Riders are matched by index plus a hidden name check; names, token/cache paths, `*_env` and the journey are never on the page. Logins card (`logins.py`, no HTTP/HTML): health from renewal's own files via `scripts/refresh_cookies.py` helpers (`token_status`, `load_refresh_chain`/`describe_chain`, the `.renewal-failed` marker honoured only while newer than the token, `.browser-attempt`, `token-alert-state.json`, `/etc/peloton-led/token-mode`), unit state from `systemctl show`; *Renew now* is `systemctl start --no-block peloton-token-refresh.service`; the Logins card shows renewal as labelled rows (`page.renewal_status`, times via `systemctl show --timestamp=unix` → `server.unix_time`; a running one is followed by `/renew/status`), and each rider is a `<details class="rider-card">` (`page._login_status`: closed while healthy, open when not), whose Email & password row is a `<details class="cred">` holding that rider's own form (only their `cred_<key>_*` fields; a 400 reopens it via `editing_rider`; Cancel is JS-only); renewal times come from `logins.renews_at` (first hourly check within `RENEW_BEFORE_S` of expiry; `CHECK_EVERY_S`/`RENEW_BEFORE_S` mirror the timer's `OnUnitActiveSec=1h` and the service's `--renew-before-hours 12`, and a test fails if they drift); the renewal timer is OnBootSec/OnUnitActiveSec, so systemd leaves `NextElapseUSecRealtime` blank and `Settings.next_elapse` reads `NextElapseUSecMonotonic` (a timespan since boot) instead, which is why PelotonPi once said "Not scheduled" while the timer ran; *Compact workout pages* is shown only on 64x32, so the form posts `COMPACT_SHOWN` beside it and `apply_form` leaves the saved value alone without it (an unticked switch posts nothing); the Rotation list's column headings (`ROTATION_COLUMNS`, ⓘ tooltips) sit outside the `<ol>` so the drag code never sees them; the top bar's Power menu (`page.power_menu`, shown with Sign out, so not on the hotspot page; a `<details>` of one-button `_post` forms with `data-confirm`, so it works without JS and asks first with it) posts `action` to `/power` (`Handler._power`, `Settings.power`, `POWER_ACTIONS`): `restart-display` / `stop-display` / `start-display` (`systemctl <verb> --no-block <display unit>`; Start replaces Stop when `display_running` is False) and `reboot` / `poweroff` (`systemctl --no-block reboot|poweroff`); same-origin check, a PIN session even on the hotspot (like `/credentials`), 409 while an update runs, 400 for an unknown action, no systemctl → `?power=unavailable`, a failure → `?power=failed-<action>` with stderr in the log; reboot/poweroff send their message page *before* running the command (so a failure there is only logged); Pushover keys and the test alert are their own card (`page.alerts_card`, its form posts `card=alerts` to `/credentials`, outcomes `?alerts=`); credentials are write-only: `update_auth_env` rewrites only the changed lines (setup_config.py's quoting, 600, no .bak), the page only ever gets set/not-set, the log only names what changed, and `/credentials` needs a PIN session even on the hotspot. Relative token paths start from `--token-base` (/etc/peloton-led, as the display sees its config), not the checkout. PIN-page states live at `/signin`. The PIN goes to `/run/peloton-led-settings/pin` (`RuntimeDirectory`, group peloton-led, 0640) and `display/ui/settings_pin.py` draws it in `ScreenManager.tick`; `show_and_wait` repaints when it appears/goes, like the padlock. Wi-Fi: `utils/wifi_setup.py` reads comitup's `/run/comitup-state` (written by LLL's `board-setup.sh`); while `HOTSPOT`, a browser in 10.41.0.0/16 needs no PIN and `run_multi_user_loop` holds the `wifi_setup` screen each cycle. A hotspot after a cold boot with the saved Wi-Fi in range was a comitup/`wlan0` boot race (PelotonPi, 2026-11-11), fixed by LLL's `board-setup.sh` drop-in (`comitup.service.d/wait-for-wifi.conf`, LLL #222); updates don't add it, so troubleshooting in `docs/install.md` gives the hand steps. Save: validate, `.bak`, atomic write keeping owner/mode, then `restart_app`: `not_running` (manual board off) / `restarted` / `failed` / `saved` (no systemd). The display's config is a read-only bind of the checkout file, so the settings service gets the real path and its folder via its own `project-config.conf` drop-in; the atomic replace is picked up when the display restarts. Installer: `resolve_settings_page` (flag, else on unless installed-and-disabled), `start_settings_page` after `start_or_restart_display`.

Tokens come from `scripts/refresh_cookies.py` (browser login once, then Auth0 refresh tokens; see Pi config above).
